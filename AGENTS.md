# nx

nx 1.0 is a package manager for a Fedora bootc system, in Rust: Fedora RPMs
overlaid live onto the image's `/usr` (the host tier) and sealed nixpkgs
tools beside it (the tool tier). It is a rebuild of nx 0.x, a Go front end to
a Nix profile that lives on as tag `v0.2.0` and is still what Neptuno ships.

Start with `docs/design.md` (the design, milestones and open questions), then
`docs/adr/0006-rust-rebuild-two-tiers.md` (why a rebuild, and what changed
from the "bx" draft), then the other ADRs.

## Gates

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and
  `cargo test` before every commit, run through `dev/run` (below). CI runs
  the same, plus shellcheck on `spike/`.
- Build in the dev container: `dev/run cargo test`. It is the image's
  Fedora release with `libsolv-devel` and `rpm-devel`; the host has their
  runtimes but no headers or `.so` links, so a host `cargo build` fails to
  link.
- `unsafe` only in `crates/nx-solv` (ADR-0007) and `crates/nx-librpm`
  (ADR-0008). Every `unsafe` block gets a `// SAFETY:` comment; the rest of
  the workspace denies `unsafe_code`.
- No `unwrap()`/`expect()` outside tests (clippy denies them). Errors via
  `thiserror` in library crates, `anyhow` in the `nx` binary.
- Everything that touches the system goes behind a trait or a root path, so
  tests run unprivileged against fixtures. Record real output into
  `tests/fixtures/` rather than writing it by hand.
- Add a crate or a dependency when a milestone needs it, not ahead of time.
  A dependency with a system library (libsolv) needs an ADR.
- Conventional Commits. End every commit with `Assisted-by: <Model> via <Tool>`.
- Confirm before pushing: show the diff and wait.
- Never run a spike or an activation on the daily driver; use a bootc VM
  built from the Neptuno image (design doc, *Milestones*).

## Output

nx 1.0 keeps nx 0.x's look; `docs/product.md` *Output* is the reference.

- clap parses, nx draws. Never let clap print: help and errors go through
  `help.rs` and `ui.rs` (`Cli::try_parse`, then render). A command's line in
  `nx help` is its doc comment; its group is in `help::PLACEMENT`.
- Every line is indented two spaces and starts with its kind's symbol
  (`› ↑ + - ↓ ⚙ ✓ ! ✗`). Results on stdout, steps, warnings and errors on
  stderr. Detail views follow `info`: bold head, dim version, then rows with
  dim keys padded to 11 (`Stream::row`).
- Colour comes from anstream's decision (TTY, `NO_COLOR`, `TERM=dumb`,
  `CLICOLOR_FORCE`); never write escape codes by hand outside `Style`.
- Exit codes: 0 success, 1 failure, 2 misuse, 130 interrupted.
- Test output as plain text through `Ui::plain` and compare whole blocks.

## Layout

- `crates/nx-cli`: the `nx` binary. `main.rs` holds the clap definitions and
  exit codes, one module per command (`status.rs`), `help.rs` draws help and
  rewords clap's errors, `ui.rs` is the output kit ported from nx 0.x.
- `crates/nx-rpm`: the host tier's repos: `.repo` files from the image
  and the manifest's added repos (`repo.rs`), metalink and `repomd.xml`
  (`repomd.rs`), verified metadata downloads and their cache (`fetch.rs`),
  package downloads, repo keys and Koji (`packages.rs`), and `universe.rs`,
  which loads the image's rpmdb and the repos into one libsolv pool through
  `.solv` caches and answers search, info and install plans.
- `crates/nx-solv`: the safe libsolv API (`lib.rs`) over bindgen output
  (`sys.rs`, regenerated by `generate.sh`, never edited by hand).
- `crates/nx-librpm`: the safe librpm API: keyrings, signature checks and
  payload unpacking, over bindgen output (`sys.rs`, from `generate.sh`).
- `dev/`: the build container (`Containerfile`) and `dev/run`, which runs a
  command in it with the repository mounted at the same path.
- `crates/nx-core`: the system as nx sees it: deployments and image digests
  (`deployment.rs`), os-release (`os_release.rs`); and nx's state: the
  state directory, its lock and the store (`state.rs`), generations
  (`generation.rs`), `manifest.toml` and `lock.toml`.
- `crates/nx-proto`: the CLI ↔ nxd protocol (one JSON line each way over
  `/run/nxd.sock`); `crates/nx-activate`: what nxd runs as root (validate a
  generation, label it, the sysext and prefix backends, behind `Layout` and
  `Runner` so tests use a temp tree and a fake `systemd-sysext`);
  `crates/nxd`: the daemon (authorization, one request per process).
  `systemd/` and `polkit/` hold the units, sysusers, tmpfiles and polkit
  files an image installs; `dev/vm-install` puts them in the test VM.
- `crates/nx-cli/src/apply.rs`: manifest → generation (resolve, download,
  verify, unpack, assemble), shared by every command that changes the
  manifest. `host.rs` holds `Machine`, the system as one value (root,
  os-release, deployments, arch): commands read `/`, tests a fixture.
- `spike/`: throwaway scripts that answer a design question (M0). Their
  results go into `docs/design.md`; the script can go once they have.
- `testdata/`: nx 0.x's recorded Nix internal-json logs, kept for the M6
  progress parser; `testdata/rpm/` holds a real signed Fedora package and
  keys for the librpm, download and Koji tests.

## Pitfalls

- `bootc status` needs root; the CLI is unprivileged. Use
  `rpm-ostree status --json` (about 50 ms), and read other deployments in
  place under `/sysroot/ostree/deploy/<osname>/deploy/<checksum>.<serial>`:
  their os-release and rpmdb are readable without root.
- Fedora 45's repo files are in `/usr/share/dnf5/repos.d`, not
  `/etc/yum.repos.d`; a file of the same name in `/etc` replaces one in
  `/usr`. `updates-archive` is enabled and holds older builds, which is
  where an image relative's exact build is found when `updates` has moved
  on.
- Image relatives are enforced by hiding other builds of an image
  package's source (`Universe::hidden`) from the solver, search and info
  alike, and the installed repo is locked, so a solve can only add
  packages. Filter by `Universe`'s arch, never a hardcoded one.
- Commands load metadata with `Refresh::IfMissing`: a read never waits on
  the network for a repo that has a cache. Expired or unreachable metadata
  is reported through `Synced::freshness`, not hidden.
- Command output is tested through a `render` that takes plain data
  (`Package`s), so tests need no rpmdb or network.
- An image relative whose exact build no repo has (`Universe::missing`)
  comes from Koji's signed copies (`data/signed/<short key id>/`). The
  solver's problems name the hidden builds in the way (`Problems::involved`);
  re-solving with the newer builds visible doesn't work, because a newer
  `-devel` requires its own newer library, which the locked image refuses.
- libsolv selections honour `pool->considered`, so `Pool` clears it before
  selecting and on `prepare`; a stale map hides packages added since (Koji).
- Changing state needs write access to `/var/lib/nx`: the `nx` user owns it
  and wheel has an ACL (`systemd/nx.tmpfiles`); in the VM `tester` is in
  wheel. `NX_STATE_DIR` points nx elsewhere, and then nothing is activated
  (nxd serves only `/var/lib/nx`): `current` moves, nothing merges.
- `nx add`, `remove` and `repo` build a generation and nxd activates it
  (`Session::install`); `generation::build` never touches `current`. nxd
  doesn't take the state lock the CLI holds while it asks.
- The nxd unit must not use `ProtectSystem=`, `PrivateTmp=` or any
  mount-namespace option: the merge would happen in the unit's own
  namespace and nothing else would see it.
- polkit reads actions only from `/usr/share/polkit-1/actions`, which is
  read-only in the VM; `dev/vm-install` bind-mounts a copy (until reboot,
  run it again). An ssh login is not a local, active session, so the wheel
  rule can't allow it: the VM has a rule for `tester` (`dev/vm-test.rules`).
- `nx rollback` follows `parent` in `lock.toml`, not the numbering: after a
  rollback, the next generation is numbered past the abandoned ones.
- nxd runs as root in a directory wheel can write: it writes `current`
  and `backend` beside their names (`create_new` or a fresh symlink, never
  a plain `write` that follows a planted link), flushes, then renames.
- Run as root in the dev container, every file is root's, so a test of
  "someone else owns it" can't run there.
- `setfiles -r` fails with "Not a directory" on a path through the `current`
  symlink; pass `realpath`. systemd-sysext finds nx through the symlink
  `/var/lib/extensions/nx` (its boot-time search path), not `/run/extensions`.
- `systemd-sysext status --json=short` lists `{"hierarchy","extensions"}`;
  nxd checks `nx` under `/usr` after a refresh, since a refresh can succeed
  and merge nothing. A forced sysext that doesn't merge is an error; an
  unforced one falls back to prefix.
- A generation's extension directory must be named `nx` when merged: its
  release file is `extension-release.nx`.
- A manifest change goes through `Session::open`'s `change` closure, which
  runs under the state lock. Reading the manifest before taking the lock
  loses a concurrent command's change.
- Unpacking checks every parent directory with `symlink_metadata`: a
  package that ships `usr/x -> /etc` and then `usr/x/f` would otherwise
  write outside the store. Files are created with `create_new` (`O_EXCL`
  never follows a symlink).
- Nothing gets its final name before its data is on disk: the store stages
  packages and commits them after one `syncfs`, and a generation is synced
  before its rename. An `fsync` per unpacked file is far slower.
- Fedora 42 and later have `/usr/sbin -> bin`. A package's `usr/sbin/foo`
  goes to `usr/bin/foo` in the extension; a real `usr/sbin` directory would
  hide the image's symlink.
- `/` on a bootc system shows the merged extension too. Invariant 1 checks
  against the booted deployment's tree under `/sysroot`
  (`Machine::image_root`), and a bootc system is recognised by
  `/run/ostree-booted`, never by whether rpm-ostree answers.
- A deployment's digest is `container-image-reference-digest`; the
  `checksum` field is the ostree commit, which is not what generations are
  keyed by.

Nix log pitfalls from nx 0.x, for M6:

- Nix logs download retries at error level with "warning:" in the text, and
  logs recovered failures as "error (ignored):". Classify by text, not level.
- A plan's paths arrive one message each, and a build plan and a fetch plan
  are two separate announcements.
- `--impure` (needed for `NIXPKGS_ALLOW_UNFREE`) also turns off the eval
  cache. Use it only when an unfree package is involved.
